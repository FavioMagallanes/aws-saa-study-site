AWS no es un único lugar en internet: es una red de centros de datos repartidos por el mundo, organizada en niveles. Entender esos niveles te permite decidir dónde ejecutar una carga de trabajo para que sea rápida para tus usuarios, cumpla las reglas que le apliquen y siga funcionando cuando algo falla.

## Qué problema resuelve

Si todo vive en un solo centro de datos, un corte de energía, un fallo de red o un desastre local deja sin servicio a todos los usuarios. Además, un usuario lejano siempre recibirá respuestas más lentas, y algunos datos no pueden salir del país donde se generan. La infraestructura global de AWS ofrece ubicaciones aisladas entre sí y a distintas distancias de tus usuarios, para que repartas tus recursos según lo que necesites proteger.

## Conceptos clave

### Regiones

Una región es una ubicación geográfica del mundo donde AWS tiene varias zonas de disponibilidad. Cada región está diseñada para estar aislada de las demás, y eso da la mayor tolerancia a fallos posible: AWS no replica tus recursos entre regiones de forma automática. Cuando consultas tus recursos en la consola, solo ves los de la región que tienes seleccionada. Para trabajar con un servicio desde la línea de comandos o la API, indicas el punto de enlace de esa región.

### Zonas de disponibilidad

Una zona de disponibilidad (AZ) son una o más instalaciones de centros de datos, con energía, red y conectividad redundantes, dentro de una región y separadas físicamente de las otras zonas. Cada región tiene al menos tres. El código de una zona es el de su región seguido de una letra, por ejemplo `us-east-2a`. Como ese código puede apuntar a ubicaciones físicas distintas según la cuenta en las regiones más antiguas, cada zona también tiene un ID de zona (por ejemplo `use1-az1`) que identifica la misma ubicación física en todas las cuentas.

Al lanzar instancias de EC2 repartidas en varias zonas, una instancia puede asumir el trabajo de otra si una zona falla. Ese reparto es la base de la alta disponibilidad dentro de una región.

### Ubicaciones más cercanas a tus usuarios o a tu centro de datos

Además de regiones y zonas, AWS ofrece tres formas de acercar la infraestructura:

- **AWS Local Zones**: una extensión de una región, situada en proximidad geográfica a tus usuarios. Tiene sus propias conexiones a internet y admite AWS Direct Connect, para servir a usuarios locales con baja latencia.
- **AWS Wavelength**: despliega servicios estándar de cómputo y almacenamiento en el borde de las redes 5G de los operadores de telecomunicaciones, para aplicaciones que necesitan latencias ultrabajas en dispositivos 5G.
- **AWS Outposts**: lleva la infraestructura, los servicios y las API de AWS a un centro de datos propio. AWS opera esa capacidad como parte de una región, y las instancias del Outpost se comunican con las de la región mediante direcciones IP privadas dentro de la misma VPC.

### Ubicaciones de borde y servicios globales

Para entregar contenido, AWS usa una red de puntos de presencia, también llamados ubicaciones de borde. Cuando un usuario pide un objeto, Amazon CloudFront dirige la solicitud, mediante DNS, al punto de presencia que mejor puede atenderla, normalmente el más cercano en latencia. Si el objeto está en caché, se devuelve de inmediato; si no, CloudFront lo pide al origen y lo guarda para la siguiente vez.

Algunos servicios no pertenecen a una región concreta: se consideran globales. En la mayoría de ellos, el plano de control vive en una sola región y el plano de datos está distribuido por el mundo. Conviene tenerlo presente al diseñar la recuperación ante fallos, para no depender de un plano de control global justo cuando más lo necesitas.

## Cómo elegir dónde colocar los recursos

Cuando debas decidir la ubicación para cumplir los requisitos del negocio, compara las regiones según cuatro factores: el cumplimiento normativo, la latencia hacia tus usuarios, el costo y los servicios y características disponibles. Si los datos están sujetos a leyes de residencia, solo entran en la lista las regiones del país que exige la ley. En aplicaciones que procesan muchos datos, como las de análisis o aprendizaje automático, lo mejor es ejecutar el código cerca de donde están esos datos.

El costo también depende de la ubicación. En general, la transferencia de datos entre zonas de disponibilidad de una misma región se cobra (algunos servicios no cobran el tráfico dentro de la región), y la que sale de una región hacia otra también. En cambio, la que ocurre dentro de la misma zona no tiene cargo, y recibir datos desde internet no se cobra. Por eso conviene mantener juntos los componentes que más se hablan entre sí cuando el ahorro importa más que repartirlos.
