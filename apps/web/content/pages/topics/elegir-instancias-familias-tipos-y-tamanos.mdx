Elegir bien una instancia de Amazon EC2 es una de las decisiones con más impacto en el rendimiento y en el costo de una carga de trabajo. AWS ofrece cientos de tipos de instancia, pero se ordenan con una lógica sencilla: una familia según el recurso que prioriza (CPU, memoria, almacenamiento o aceleradores), una generación, unas opciones y un tamaño. El examen espera que sepas leer un requisito y llegar a la familia y al tamaño adecuados, y que sepas hacer lo mismo con la memoria de una función de Lambda.

## Qué problema resuelve

Si la instancia es demasiado pequeña, la aplicación se queda sin CPU o sin memoria y empeora la experiencia del usuario. Si es demasiado grande o de la familia equivocada, pagas recursos que no usas. Cada tipo de instancia combina de forma distinta CPU, memoria, almacenamiento y red, así que lo importante es identificar qué recurso limita a la carga y elegir la combinación que la atiende con el menor desperdicio. Y si las necesidades cambian, puedes cambiar el tipo de instancia más adelante.

## Conceptos clave

### Cómo leer el nombre de una instancia

En un nombre como `c7gn.4xlarge`:

- **Serie** (`c`): la familia, por ejemplo C de cómputo optimizado.
- **Generación** (`7`): cuanto mayor, más reciente.
- **Opciones** (`gn`): características adicionales. Algunas comunes: `g` procesadores AWS Graviton, `a` procesadores AMD, `i` procesadores Intel, `d` volúmenes de almacén de instancia, `n` red y EBS optimizados, `e` memoria o almacenamiento extra, `z` alta frecuencia de CPU, `flex` instancia Flex.
- **Tamaño** (después del punto): por ejemplo `small`, `large` o `4xlarge`, o `metal` para una instancia bare metal.

Cada tipo incluye uno o varios tamaños, de modo que puedes ajustar los recursos a la carga sin cambiar de familia.

### Familias de instancias

- **Uso general (M, y T con rendimiento ampliable)**: equilibran cómputo, memoria y red. Ideales para aplicaciones que usan esos recursos en proporciones similares, como servidores web y repositorios de código.
- **Cómputo optimizado (C)**: para aplicaciones intensivas en cómputo que aprovechan procesadores de alto rendimiento: procesamiento por lotes, transcodificación de medios, servidores web de alto rendimiento, HPC, modelado científico, servidores de juegos dedicados, motores de anuncios e inferencia de aprendizaje automático.
- **Memoria optimizada (R, X, U, z1d)**: diseñadas para un rendimiento rápido en cargas que procesan grandes conjuntos de datos en memoria, como bases de datos grandes o cachés en memoria, con una proporción de memoria por CPU más alta.
- **Almacenamiento optimizado (I, D, H)**: para cargas que necesitan acceso secuencial de lectura y escritura elevado a conjuntos de datos muy grandes en almacenamiento local; entregan decenas de miles de IOPS aleatorias de baja latencia.
- **Computación acelerada (P, G, Inf, Trn, F)**: usan aceleradores de hardware, como GPU, para hacer cálculos de coma flotante, procesamiento de gráficos o búsqueda de patrones de forma más eficiente que el software en CPU. Encajan con el entrenamiento de modelos de aprendizaje automático, que suele requerir aceleradores especializados.
- **Computación de alto rendimiento (Hpc)**: diseñadas para ofrecer la mejor relación precio-rendimiento en cargas HPC a escala, como simulaciones grandes y complejas.

### Instancias de rendimiento ampliable (T)

Muchas cargas de uso general no están ocupadas la mayor parte del tiempo y no necesitan CPU alta de forma sostenida. Las instancias T ofrecen un rendimiento base de CPU con la capacidad de superarlo cuando hace falta. Son la forma más rentable de ejecutar un amplio abanico de aplicaciones de uso general con uso de CPU bajo o moderado: microservicios, servidores web, bases de datos pequeñas y medianas, entornos de desarrollo y prueba. Los tamaños pequeños, como `nano`, `micro`, `small` y `medium`, convienen a cargas con poca memoria y poca CPU.

### Virtualización y AWS Nitro System

EC2 usa dos hipervisores: Xen, en tipos más antiguos, y Nitro, en la mayoría de los actuales. El Nitro System es un conjunto de componentes de hardware y software de AWS que permite alto rendimiento, alta disponibilidad y alta seguridad; su hipervisor ligero ofrece, en la mayoría de las cargas, un rendimiento indistinguible del de un servidor físico. Las instancias bare metal (`metal`) eliminan la sobrecarga de la virtualización y sirven cuando la carga necesita acceso a funciones de hardware de bajo nivel o un entorno no virtualizado por licencias o soporte. Los tipos de la generación actual solo admiten virtualización HVM, que viene determinada por la AMI.

### Recursos compartidos y E/S

EC2 dedica a cada instancia parte de los recursos del servidor, como CPU, memoria y almacenamiento de instancia, y comparte otros, como la red y el subsistema de disco. Los tipos con E/S alta reciben una porción mayor de esos recursos compartidos y un rendimiento más estable. Para la mayoría de las aplicaciones basta con E/S moderada; si necesitas más o más constante, elige un tipo con E/S alta.

### Elegir el tamaño correcto

- **Prueba con tu carga**: AWS recomienda lanzar instancias y medir con tu propia aplicación de referencia. Como pagas por segundo, probar varios tipos antes de decidir es cómodo y barato.
- **Cambia cuando haga falta**: si la instancia queda grande o pequeña, puedes cambiar su tipo, por ejemplo de `t2.micro` a `t2.large` o a `m5.large`. Pasas a pagar la tarifa del nuevo tipo. Para añadir almacenamiento no hace falta cambiar de tipo: basta con conectar otro volumen de EBS.
- **AWS Compute Optimizer**: analiza la configuración y las métricas de uso de instancias EC2, grupos de Auto Scaling, volúmenes de EBS, funciones de Lambda y otros recursos, y genera recomendaciones de tamaño (rightsizing) para reducir costos y mejorar el rendimiento. También detecta recursos inactivos. Hay que activarlo (opt in).

### Tamaño de una función de Lambda

En Lambda no eliges un tipo de instancia: eliges la memoria, entre 128 MB y 10.240 MB, y Lambda asigna CPU en proporción a esa memoria. La memoria es la palanca principal del rendimiento de una función.

- 128 MB, el valor predeterminado y mínimo, solo se recomienda para funciones simples, como las que transforman y enrutan eventos.
- Si una función está limitada por CPU, red o memoria, aumentar la memoria puede mejorar mucho su rendimiento, porque también aumenta la CPU.
- Para encontrar el valor adecuado, supervisa con Amazon CloudWatch el consumo de memoria y la duración. La herramienta de código abierto AWS Lambda Power Tuning ejecuta la función con distintas memorias y mide el rendimiento.

### Qué tecnología de cómputo usar

Antes de elegir el tamaño, decide el modelo: Amazon EC2 para servidores virtuales con control total; Amazon ECS o Amazon EKS para contenedores, sobre EC2 o sobre AWS Fargate sin administrar servidores; AWS Lambda para ejecutar código sin aprovisionar servidores, con escalado automático; y AWS Batch para procesar grandes volúmenes de datos en paralelo. Una misma carga puede combinar varios.
