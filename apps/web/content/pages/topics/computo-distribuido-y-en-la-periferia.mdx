No todo el cómputo tiene que vivir en una sola región de AWS. Cuando los usuarios están repartidos por el mundo, cuando una aplicación necesita latencias muy bajas o cuando los datos deben quedarse en un lugar concreto, conviene acercar el cómputo al usuario o al dato. AWS ofrece para ello una escalera de opciones que va desde las regiones y zonas de disponibilidad hasta las ubicaciones de borde de CloudFront, las Local Zones, las Wavelength Zones y AWS Outposts en tu propio centro de datos.

## Qué problema resuelve

Cada viaje de red entre el usuario y el servidor añade latencia. Para un sitio web eso puede ser aceptable, pero no para un videojuego en tiempo real, una transmisión en vivo o una aplicación móvil que depende de respuestas inmediatas. Otras veces el límite no es la latencia sino la normativa: los datos deben procesarse en un país, una ciudad o el propio edificio. Las estrategias de cómputo distribuido reparten el trabajo entre varias ubicaciones para reducir la latencia, procesar los datos donde se generan y cumplir los requisitos de residencia, sin renunciar a las mismas API y herramientas de AWS.

## Conceptos clave

### La base: regiones y zonas de disponibilidad

- **Región**: una ubicación geográfica donde AWS agrupa centros de datos. Cada región está aislada de las demás, de modo que un fallo de servicio queda limitado a una región. Los recursos y datos que creas en una región no existen en otra salvo que los repliques. Las regiones se conectan mediante la red global de AWS, con conectividad privada de gran ancho de banda y baja latencia.
- **Zona de disponibilidad**: uno o varios centros de datos con energía, red y conectividad independientes y redundantes. Las zonas de una región están lo bastante separadas para evitar fallos simultáneos, pero lo bastante cerca para replicar datos de forma síncrona con latencia de milisegundos de un solo dígito.

Repartir la carga entre varias zonas, o entre varias regiones cercanas a los usuarios, es la primera forma de cómputo distribuido.

### Cómputo en el borde con CloudFront

Amazon CloudFront entrega contenido a través de una red mundial de centros de datos llamados ubicaciones de borde, y dirige cada solicitud a la ubicación con menor latencia. Además de almacenar en caché, permite ejecutar código propio cerca del usuario, sin administrar servidores, mediante funciones de borde:

- **CloudFront Functions**: funciones ligeras en JavaScript, con arranque en menos de un milisegundo y capacidad para millones de solicitudes por segundo. Ideales para normalizar la clave de caché, manipular encabezados, redirigir o reescribir URL y validar tokens de autorización, como JWT. No tienen acceso a la red ni al cuerpo de la solicitud.
- **Lambda@Edge**: una extensión de AWS Lambda en Node.js o Python para lógica más compleja. La publicas en una región y, al asociarla a una distribución, se replica automáticamente por todo el mundo. Es la opción cuando la función tarda varios milisegundos o más, necesita más CPU o memoria, usa bibliotecas de terceros, accede a la red o al sistema de archivos, o lee el cuerpo de la solicitud. También puede ejecutarse en los eventos de solicitud y respuesta al origen, no solo en los del espectador.

### AWS Local Zones

Las Local Zones colocan cómputo, almacenamiento, bases de datos y otros servicios seleccionados cerca de grandes centros de población e industria. Sirven para:

- Ejecutar aplicaciones de baja latencia cerca de los usuarios: juegos en tiempo real, transmisión en vivo, realidad aumentada y virtual, estaciones de trabajo virtuales.
- Simplificar migraciones híbridas a una ubicación cercana manteniendo los requisitos de baja latencia.
- Cumplir requisitos estrictos de residencia de datos.

No hay cargo por habilitarlas; pagas los recursos que despliegues, cuyos precios pueden ser distintos a los de la región principal.

### AWS Wavelength

Wavelength despliega servicios estándar de cómputo y almacenamiento en el borde de las redes 5G de los proveedores de telecomunicaciones, para ofrecer latencias muy bajas a dispositivos móviles y usuarios finales. Una Wavelength Zone es una extensión lógica de una región: extiendes tu VPC con una subred en la zona, ejecutas allí instancias EC2 y te comunicas con los servicios de la región. Un _carrier gateway_ permite el tráfico entre la red del operador y la zona.

### Cómputo híbrido: AWS Outposts

AWS Outposts es un servicio totalmente administrado que lleva la infraestructura, los servicios, las API y las herramientas de AWS a tus instalaciones. Un Outpost es capacidad de cómputo y almacenamiento de AWS instalada en tu sitio, que AWS opera, supervisa y administra como parte de una región.

- Creas subredes en el Outpost y lanzas en ellas instancias EC2, volúmenes EBS, clústeres ECS o instancias RDS. Se comunican con la región por direcciones IP privadas dentro de la misma VPC.
- Conviene cuando necesitas baja latencia hacia sistemas locales o procesar los datos en tu sitio, pero quieres usar las mismas interfaces que en una región.
- Hay dos formatos: **racks** de Outposts (rack estándar de 42U) y **servidores** de Outposts (1U o 2U), para sitios con poco espacio o menos capacidad.

### Contenedores fuera de la región

- **Amazon ECS Anywhere**: registra servidores locales o máquinas virtuales como instancias externas de un clúster de ECS. Está optimizado para aplicaciones que generan tráfico saliente o procesan datos; como no admite Elastic Load Balancing, es menos eficiente para cargas que reciben tráfico entrante.
- **Amazon EKS**: puede usar cómputo en regiones, Local Zones y Wavelength Zones; en tu centro de datos, con nodos en AWS Outposts o con nodos híbridos en tu propia infraestructura. **Amazon EKS Anywhere** está pensado para entornos aislados (air-gapped) y autocontenidos.

### Procesamiento distribuido en la región

No todo el cómputo distribuido está en el borde. AWS Batch planifica y ejecuta trabajos por lotes en contenedores sobre ECS, EKS, Fargate e instancias Spot o bajo demanda, para procesar grandes volúmenes de datos en paralelo.
