AWS Step Functions es el servicio de orquestación de flujos de trabajo de AWS. Con él creas flujos de trabajo, también llamados máquinas de estado, para construir aplicaciones distribuidas, automatizar procesos, orquestar microservicios y crear canalizaciones de datos y de machine learning.

## Qué problema resuelve

Un proceso de negocio con varios pasos en distintos servicios necesita que alguien decida el orden, las ramas, los reintentos y qué hacer si algo falla. Si ese código de coordinación vive dentro de cada servicio, todos quedan más acoplados. Step Functions saca esa lógica a un flujo visible en la consola, donde puedes ver, editar y depurar cada paso. Las ventajas de orquestar frente a coreografiar, los tipos de estado y el patrón Saga se explican en el tema «Orquestación de flujos de trabajo».

## Conceptos clave

### Flujos, estados y ejecuciones

- **Flujo de trabajo (máquina de estado)**: una serie de pasos basados en eventos, definida en Amazon States Language.
- **Estado**: cada paso. Un estado Task representa una unidad de trabajo, como llamar a otro servicio de AWS o a una API; otros estados eligen ramas, ejecutan en paralelo, esperan o terminan el flujo.
- **Ejecución**: cada instancia en marcha de un flujo.
- **Manejo de errores**: por defecto, un error hace fallar toda la ejecución; los estados Task, Parallel y Map admiten reintentos y la captura de errores para pasar a un estado de recuperación, sin escribir ese código en los servicios.

### Standard frente a Express

Eliges el tipo al crear la máquina de estado y no se puede cambiar después:

- **Standard**: flujos largos, duraderos y auditables, de hasta un año. Modelo **exactamente una vez**, adecuado para acciones no idempotentes como procesar pagos. Se cobra por transición de estado. También sirve para flujos largos que requieren interacción humana.
- **Express**: cargas de alto volumen de eventos, como ingesta de datos de IoT o procesamiento de streaming, de hasta cinco minutos. Se cobra por número de ejecuciones, duración y memoria. Las asíncronas son **al menos una vez** y las síncronas **como máximo una vez**, así que conviene que las acciones sean idempotentes.

### Integraciones

Step Functions puede llamar a más de doscientos servicios de AWS mediante integraciones del AWS SDK, y tiene integraciones optimizadas con servicios como Lambda, Amazon ECS, AWS Batch o AWS Glue. Puede avanzar en cuanto recibe la respuesta, esperar a que termine un trabajo (`.sync`) o esperar un token de devolución de llamada; los flujos Express solo admiten el primer patrón. Los flujos pueden iniciarse por eventos, como solicitudes HTTP de Amazon API Gateway o eventos de Amazon EventBridge.
