AWS IAM Identity Center es la solución de AWS para conectar a las personas de tu organización (tu fuerza laboral) con cuentas de AWS y con aplicaciones. Puedes conectar tu proveedor de identidades existente y sincronizar sus usuarios y grupos, o crear y administrar los usuarios directamente en el servicio. Antes se llamaba AWS Single Sign-On.

## Qué problema resuelve

Con varias cuentas y varias aplicaciones, crear usuarios de IAM en cada cuenta multiplica identidades y credenciales de largo plazo. Como práctica recomendada, AWS pide que las personas accedan mediante federación con un proveedor de identidades. Identity Center es el único punto de federación: federas una sola vez, administras un solo certificado si usas un proveedor SAML 2.0, y las personas reciben credenciales de corto plazo. Las tres formas de federar y cuándo usar cada una se comparan en el tema de federación de identidades y servicios de directorio.

## Conceptos clave

### Origen de identidades

El origen de identidades define dónde se administran los usuarios y grupos. Solo puede haber uno por organización:

- **Proveedor de identidades externo**, como Okta o Microsoft Entra ID.
- **Active Directory**, local o AWS Managed Microsoft AD. Simple AD no se admite como origen.
- **Directorio de Identity Center**, el predeterminado, donde creas tú los usuarios y grupos.

### Conjuntos de permisos

Un conjunto de permisos es una plantilla que agrupa una o más políticas de IAM, por ejemplo para administradores de bases de datos. Al asignarlo a un usuario o grupo en una o varias cuentas, Identity Center crea en cada cuenta los roles de IAM correspondientes, les adjunta las políticas y deja que los usuarios autorizados asuman esos roles. Si modificas el conjunto, el servicio mantiene actualizados los roles y políticas.

### Instancias y portal

- **Instancia de organización**: es la práctica recomendada y la única que permite administrar el acceso a cuentas de AWS. Se despliega en la cuenta de administración de AWS Organizations.
- **Instancia de cuenta**: ligada a una sola cuenta, solo para despliegues aislados de algunas aplicaciones administradas por AWS.
- **Portal de acceso de AWS**: un portal web donde cada persona ve las cuentas y aplicaciones que tiene asignadas, con inicio de sesión único en la consola y en aplicaciones compatibles con SAML, como Microsoft 365, SAP Concur y Salesforce.
