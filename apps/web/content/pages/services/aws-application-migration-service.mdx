AWS Application Migration Service (MGN), que la documentación actual de AWS llama **AWS Transform MGN**, automatiza la migración de servidores físicos, virtuales y de otras nubes a AWS con un tiempo de inactividad mínimo. Replica los servidores de origen de forma continua y los convierte para que arranquen en AWS.

## Qué problema resuelve

Llevar a la nube decenas o cientos de servidores con sus aplicaciones, tal como están, es lento y arriesgado si se hace a mano: hay que copiar discos, adaptar los sistemas para que arranquen en otra plataforma y detener las aplicaciones durante el traslado. MGN replica los servidores a nivel de bloque mientras siguen funcionando, de modo que el corte final suele durar minutos. Es la vía rápida para **rehospedar** (lift and shift); una vez en AWS, puedes cambiar de plataforma o refactorizar las aplicaciones como siguiente paso de modernización.

## Conceptos clave

### Replicación continua

En cada servidor de origen instalas el **AWS Replication Agent**. El agente envía los datos de forma continua, cifrados y comprimidos, a servidores de replicación situados en una **subred de staging** de tu cuenta, que AWS recomienda dedicar solo a este fin. Funciona con Windows Server y con varias distribuciones de Linux.

### Plantillas

Tres plantillas configurables controlan la migración: de **replicación**, de **lanzamiento** y de **posterior al lanzamiento**. Se aplican a cada servidor nuevo y puedes sobrescribirlas para un servidor concreto. Las instancias de prueba y de corte se lanzan en la subred que indica la plantilla de lanzamiento de Amazon EC2 que MGN crea para cada servidor.

### Prueba y corte (cutover)

El flujo recomendado es: instalar el agente, esperar a que la replicación esté en estado saludable, lanzar **instancias de prueba** y validarlas, y en la fecha planificada lanzar las **instancias de corte**. AWS recomienda probar al menos dos semanas antes del corte y no desconectar el servidor de origen hasta comprobar que la instancia en AWS funciona como se espera.

### Migración a escala

Puedes agrupar servidores en aplicaciones y aplicaciones en **oleadas** (waves), y ejecutar acciones como el lanzamiento o el corte sobre un servidor, una aplicación o una oleada completa.
