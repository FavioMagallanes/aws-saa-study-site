AWS Directory Service ofrece varias formas de usar Microsoft Active Directory (AD) con otros servicios de AWS. Un directorio guarda información de usuarios, grupos y dispositivos, y sirve para administrar el acceso a la información y a los recursos. El servicio sirve tanto a quien ya tiene un Active Directory o aplicaciones compatibles con LDAP como a quien necesita un directorio nuevo en la nube.

## Qué problema resuelve

Muchas empresas ya administran a sus personas en un Active Directory local y tienen aplicaciones que dependen de él. Llevar esas cargas a AWS o dar acceso a la consola sin duplicar identidades exige un directorio en la nube o un puente hacia el directorio existente. Directory Service te da las dos opciones como servicio administrado. Cuándo federar y con qué servicio se explica en detalle en el tema de federación de identidades y servicios de directorio; aquí ves cada tipo de directorio.

## Conceptos clave

### Tres tipos de directorio

- **AWS Managed Microsoft AD**: un Active Directory real de Windows Server, administrado por AWS. Crea un par de controladores de dominio de alta disponibilidad en tu VPC, en distintas zonas de disponibilidad, y AWS se encarga de la supervisión, la recuperación, la replicación, las instantáneas y las actualizaciones. Admite relaciones de confianza con tu AD existente, MFA, LDAP seguro y cargas como SharePoint, SQL Server y Amazon RDS for SQL Server.
- **AD Connector**: una puerta de enlace que redirige las solicitudes de directorio a tu AD local sin guardar información en la nube. No sincroniza directorios ni requiere una infraestructura de federación propia. Sigues administrando usuarios y contraseñas en tu AD local; no es compatible con RDS SQL Server.
- **Simple AD**: un directorio independiente compatible con Active Directory, con tecnología de Samba 4, para funciones básicas como cuentas de usuario, grupos, unión de instancias al dominio y SSO con Kerberos. No admite MFA ni relaciones de confianza.

### Federar el directorio con roles de IAM

Por defecto, los miembros del directorio no tienen acceso a ningún recurso de AWS. Para darles acceso a la consola de administración asignas roles de IAM a usuarios o grupos del directorio, y el rol define qué servicios, recursos y nivel de acceso tienen. AD Connector también permite que los usuarios entren a la consola con sus credenciales actuales de AD. Federa así cuando tus identidades ya viven en un Active Directory y no quieres crear usuarios de IAM. Si además administras varias cuentas, conecta el directorio como origen de identidades de IAM Identity Center; junto con AWS Managed Microsoft AD, Identity Center añade credenciales de corto plazo para el SDK y la CLI, e inicio de sesión en aplicaciones en la nube mediante integraciones SAML.
