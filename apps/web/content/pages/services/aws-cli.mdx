La AWS Command Line Interface (AWS CLI) es una herramienta de código abierto para trabajar con los servicios de AWS escribiendo comandos en la terminal, en lugar de hacer clic en la consola. Da acceso directo a las API públicas de los servicios y permite automatizar tareas con scripts.

## Qué problema resuelve

La consola de administración es cómoda para explorar, pero repetir a mano la misma tarea en varias cuentas o regiones es lento y propenso a errores. Con la AWS CLI ejecutas desde la terminal funciones equivalentes a las de la consola, las encadenas en scripts de shell y las repites de forma idéntica cada vez. Todas las funciones de administración de infraestructura (IaaS) de la consola están disponibles en la API y en la CLI.

## Conceptos clave

### Dónde se ejecuta

- **Linux y macOS**: en shells como bash, zsh o tcsh.
- **Windows**: en el símbolo del sistema o en PowerShell.
- **De forma remota**: en instancias de Amazon EC2 mediante SSH o con AWS Systems Manager.

Además de los comandos equivalentes a la API, algunos servicios añaden comandos de más alto nivel que simplifican las API complejas. La versión 2 es la versión principal más reciente.

### Perfiles y configuración

La CLI guarda la configuración y las credenciales en dos archivos, `config` y `credentials`, divididos en perfiles. Si no indicas otro, usa el perfil `default`; con `--profile` eliges otro, y cada perfil puede tener sus propias credenciales, región y formato de salida. Las opciones de la línea de comandos tienen prioridad sobre las variables de entorno, y estas sobre los archivos de configuración.

### Credenciales: mejor temporales

AWS ordena las formas de autenticar la CLI por recomendación, y prefiere siempre credenciales de corto plazo:

- **Inicio de sesión con las credenciales de la consola**: la opción recomendada.
- **AWS IAM Identity Center**: credenciales de corto plazo para los usuarios del personal; AWS recomienda combinarlo con AWS Organizations.
- **Rol de la instancia EC2**: en una instancia, la CLI obtiene credenciales temporales del rol asignado mediante los metadatos de la instancia.
- **Asumir un rol**: defines un perfil con el ARN del rol y la CLI pide credenciales temporales con `sts:AssumeRole`, también para acceder a otra cuenta.
- **Claves de acceso de largo plazo de un usuario de IAM**: no recomendado, porque no caducan.

Las prácticas de identidades y roles se explican en el tema "IAM: usuarios, grupos, roles, políticas y MFA".
