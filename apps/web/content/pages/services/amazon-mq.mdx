Amazon MQ es un servicio administrado de agentes de mensajes para Apache ActiveMQ Classic y RabbitMQ. Se encarga de configurar, operar y mantener los agentes, y te permite migrar los que ya tienes sin reescribir el código de mensajería.

## Qué problema resuelve

Muchas aplicaciones empresariales se comunican a través de un agente de mensajes tradicional con API como JMS o protocolos estándar como AMQP, MQTT, OpenWire o STOMP. Llevarlas a AWS reescribiéndolas para usar Amazon SQS o Amazon SNS cuesta tiempo. Amazon MQ ofrece esos mismos motores como servicio administrado, de modo que la aplicación sigue hablando con su agente mientras AWS aplica el mantenimiento y las actualizaciones de versión en la ventana que programes. La comparación general entre colas, publicación/suscripción y agentes está en el tema «Colas, mensajería y publicación/suscripción».

## Conceptos clave

### El agente

Un agente (broker) es el entorno de mensajería que se ejecuta en Amazon MQ y es su pieza básica. Permite que aplicaciones escritas en distintos lenguajes y sistemas operativos se comuniquen con protocolos de mensajería estándar. A diferencia de SQS y SNS, Amazon MQ admite mensajería síncrona además de asíncrona, y ofrece tanto colas como publicación/suscripción.

### Opciones de despliegue y alta disponibilidad

- **ActiveMQ de instancia única**: un agente en una zona de disponibilidad, con almacenamiento en Amazon EFS (redundante entre varias zonas) o Amazon EBS (optimizado para baja latencia y alto rendimiento).
- **ActiveMQ activo/en espera**: dos agentes en zonas de disponibilidad distintas que forman un par redundante con almacenamiento en EFS. Solo uno está activo; si falla o entra en mantenimiento, el otro pasa a activo. La aplicación debe poder conectarse a cualquiera de los dos puntos de enlace.
- **RabbitMQ de instancia única**: un agente en una zona de disponibilidad detrás de un Network Load Balancer, que mantiene el mismo punto de enlace aunque se reemplace la instancia.
- **Clúster de RabbitMQ**: tres nodos detrás de un Network Load Balancer, repartidos entre varias zonas de disponibilidad, con los datos replicados entre ellos.

### Seguridad y monitorización

Los mensajes se cifran en reposo y en tránsito, las conexiones usan SSL y puedes limitar el acceso a un punto de enlace privado dentro de tu VPC. IAM controla qué acciones pueden hacer los usuarios sobre cada agente, y las métricas de agentes y colas llegan a Amazon CloudWatch.
