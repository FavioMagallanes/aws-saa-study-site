AWS Secrets Manager es un servicio para administrar, recuperar y rotar durante todo su ciclo de vida las credenciales de bases de datos y de aplicaciones, los tokens de OAuth, las claves de API y otros secretos. Muchos servicios de AWS guardan y usan sus secretos en Secrets Manager.

## Qué problema resuelve

Una credencial escrita en el código fuente queda expuesta a cualquiera que pueda inspeccionar la aplicación, y cambiarla obliga a volver a desplegar. Con Secrets Manager, la aplicación pide el secreto en tiempo de ejecución, así que puedes rotarlo sin tocar el código ni los clientes. Cómo elegir entre Secrets Manager, Parameter Store y AWS AppConfig para la configuración de aplicaciones se explica en el tema «Secretos y credenciales de aplicaciones».

## Conceptos clave

### Rotación automática

Rotar es actualizar la credencial tanto en el secreto como en la base de datos o el servicio. Programar la rotación te permite sustituir secretos de largo plazo por otros de corto plazo, lo que reduce mucho el riesgo de que se vean comprometidos.

- **Rotación administrada**: para la mayoría de los secretos administrados, el servicio configura y gestiona la rotación por ti, sin una función de Lambda.
- **Rotación con una función de AWS Lambda**: para otros tipos de secreto, una función de Lambda actualiza el secreto y la base de datos o el servicio. Pagas esa función a la tarifa de Lambda.

### Cifrado con AWS KMS

Los secretos se cifran con AWS KMS. Puedes usar sin costo la clave administrada por AWS `aws/secretsmanager`, o una clave que crees tú, que se cobra a la tarifa de KMS.

### Acceso desde otra cuenta

Para que una identidad de otra cuenta lea un secreto debes permitirlo en dos sitios: en una política de recursos del secreto y en una política de identidad en la cuenta de la identidad. Además, el secreto debe estar cifrado con una clave de KMS que hayas creado, cuya política de clave permita usarla a esa identidad, porque la clave `aws/secretsmanager` no sirve para el acceso entre cuentas.

### Replicación entre regiones

Puedes replicar un secreto en varias regiones para aplicaciones repartidas entre ellas o para mejorar la resiliencia. Se replican los datos cifrados y metadatos como etiquetas y políticas de recursos. Al rotar el secreto principal, el nuevo valor se propaga a las réplicas, y puedes promover una réplica a secreto independiente.

### Auditoría y costo

AWS CloudTrail registra las llamadas a la API de Secrets Manager como eventos de administración. Pagas solo por lo que usas, sin mínimos ni cargos de configuración, y los secretos marcados para eliminación no se cobran.
